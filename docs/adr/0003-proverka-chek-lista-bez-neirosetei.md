## Контекст
Каждый звонок надо проверять по настраиваемому чек-листу: у пунктов вес, ключевые фразы и синонимы. Бриф требует, чтобы проверка по умолчанию шла без нейросети, а смысловая через Ollama была опциональной.

## Решение
Основная проверка работает на леммах (pymorphy3) и правилах: окно реплик, минимальное число совпадений, открытые вопросы, условие срабатывания. Смысловая проверка через локальный Ollama выключена по умолчанию и перепроверяет только пункты, проваленные по ключевым фразам. Модель может перевести пункт в «выполнен» только с цитатой, которая реально есть в расшифровке; иначе вердикт отклоняется. Если Ollama недоступен, анализ продолжается с предупреждением.

## Почему
- Оценка целиком нейросетью отвергнута: медленнее на сотнях звонков, не воспроизводима (один звонок может получить разный балл) и требует модели у каждого пользователя.
- Простое сравнение подстрок отвергнуто: русские словоформы («предложу» и «предлагаю») не совпали бы; леммы это решают без нейросети.
- Перепроверка и выполненных пунктов моделью отвергнута: у них уже есть цитата-доказательство, а время работы выросло бы.
- Принимать вердикт модели без цитаты отвергнуто: галлюцинация молча завысила бы балл.

## Последствия
- Правила на фразах хрупки: ложные срабатывания и пропуски неизбежны, а поведение зависит от качества расшифровки. Нужны отдельные правила, например отрицание в той же части предложения гасит фразу, а следующий шаг считается только с первым лицом и конкретикой.
- Модель может только поднять вердикт, но не найти то, что правила пропустили у выполненных пунктов (исключение — условие, не найденное по фразам: см. 0013). Пункты, помеченные как подтверждённые моделью, надо отдельно показывать в отчёте.
- Изменение чек-листа меняет оценки без правки кода, поэтому ошибки в YAML нужно ловить до начала расшифровки.
