## Контекст
Панель открыта по сети офиса, а за ней записи клиентов. Аккаунты и роли исключены брифом; пароль должен задаваться при установке.

## Решение
Один общий пароль из файла окружения. Проверка входа — один слой на всё приложение: без сессии HTML-страницы ведут на форму входа, а запись, выгрузка и любой программный путь отвечают отказом. Публичны только страница входа и оформление. Без заданного пароля сервер не стартует. Пароль меняют в файле и перезапуском, из интерфейса — нельзя. После пяти неверных попыток подряд вход блокируется на пять минут.

## Почему
- Аккаунты менеджеров и роли отвергнуты брифом и сделали бы установку и поддержку непосильными для «сисадмина один раз».
- Защита на уровне каждого маршрута отвергнута: любой новый маршрут, где её забыли, выдаёт записи наружу; общий слой закрывает новые страницы по умолчанию.
- Запуск без пароля «для удобства» отвергнут: офисная сеть не безопасна, а забытый пароль выглядел бы как рабочая система.
- Смена пароля из интерфейса и HTTPS внутри программы отвергнуты на этом этапе: первое требует хранения секрета в базе, второе — управления сертификатами; вместо этого README описывает обратный прокси.

## Последствия
- Пароль общий: нельзя ограничить доступ отдельным людям или отозвать его у одного уволенного без смены у всех.
- Без HTTPS пароль и записи идут по сети открыто; безопасность зависит от того, настроит ли сисадмин прокси.
- Блокировка считается по адресу; за общим прокси все пользователи окажутся одним адресом и заблокируют друг друга.
- Новый маршрут, который должен быть публичным, придётся добавлять в исключения явно.
