## Контекст
План (D01, сборка, T01) исходил из того, что `uv sync` создаст обычное окружение `.venv` внутри проекта. В пути проекта есть символ «:», а uv добавляет `.venv/bin` в PATH, где «:» — разделитель.

## Решение
Окружение uv живёт вне проекта: перед каждой командой uv задаётся `UV_PROJECT_ENVIRONMENT=$HOME/.cache/callscope-venv`. Это записано в правилах проекта и README; у пользователя без «:» в пути работает и обычный `.venv`.

## Почему
- Обычный `.venv` внутри проекта на практике сломался: uv падает, потому что путь с «:» разваливает PATH. Это доказал запуск, а не предположение.
- Менять расположение или название папки проекта в материалах не рассматривалось, и решение этого не требует: ограничение касается только окружения разработчика, а не продукта.
- Системный Python 3.9 и системный ffmpeg не годятся как замена: нужен Python 3.11+, а аудио декодируется без внешнего ffmpeg.

## Последствия
- Каждая команда `uv sync`, `uv run`, `pytest` требует предварительного `export`; забытая переменная даёт путаную ошибку.
- Окружение лежит вне репозитория, поэтому его не видно в проекте и оно не удаляется вместе с ним.
- Инструкции для новичка в README должны различать оба случая.
